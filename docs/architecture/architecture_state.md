# Architecture State

## Purpose
This document is the single source of truth for the current implementation state of the Go2W cross-floor navigation stack.
It records the active phase, the frozen contracts, the open decisions, and the only approved next task boundary.

## Status Judgment Rule
- All phase and capability judgments in this repository should use one of four labels: `已完成`, `部分完成`, `未完成`, `无法确认`.
- `已完成` requires cross-checked code, config, script, test, or runtime evidence.
- `部分完成` means the capability exists but does not yet cover the full target scope, or it is intentionally kept opt-in / candidate only.
- `无法确认` means there is not enough evidence to judge; do not guess.
- Plans, TODOs, comments, and old logs are not enough to mark a capability complete.

- Post-Phase-4 mission scheduling policy: `go2w_mission` now uses a bounded FIFO `MissionScheduleGate` with capacity `2` total outstanding goals, so one `RunMission` goal may execute actively while one may wait in queue. - Post-Phase-4 mission operator control hardening: `go2w_mission` now persists a small operator-state snapshot backend and exposes a `MissionControl` service for `pause`, `resume`, `status`, and cooperative `cancel_active`. - Post-Phase-4 follow-up hardening: the real-model stair fixture now verifies a phase-aware `/stair_exec` Action closed loop on the opt-in real Go2W launch path. The observed sequence covers command ownership `flat/wheeled -> stair/legged -> flat/wheeled`, phases `prepare,wheel_lock,body_height_transition_down,execute_stairs,body_height_transition_up,release`, profile-limited stair velocity, and leg-hold enable/release diagnostics. It is still a control skeleton, not physical stair locomotion or a tuned gait controller.
- Post-Phase-4 follow-up hardening: `go2w_mission` now has a JSON-backed mission checkpoint store, same-goal resume eligibility, finite retry for recoverable segment failures, and launch-configurable recovery settings. The verifier proves a failed stair-unavailable mission becomes `RECOVERABLE` at segment index `1`, then resumes from that checkpoint and reaches `MISSION_SUCCEEDED` when the stair executor is available. This is a production-style recovery skeleton, not a complete production Mission Orchestrator.
- Post-Phase-4 control-chain hardening: a stable control-chain regression wrapper now runs the real-model baseline, phase-aware stair fixture, mission recovery, and stair tuning smoke test.
